# 爆款结构迁移引擎 PRD v2

更新时间：2026-06-07  
负责人视角：当前版本评估与最终成品收敛  
目标用户：需要把爆款短视频结构迁移到自有商品、课程或内容素材上的创作者 / 运营 / 短视频投放团队

## 1. 背景与当前判断

当前系统已经具备一条可跑的技术主链路：样例视频上传、ASR / 结构分析、用户素材分析、槽位匹配、方案生成、AIGC 缺口补全建议、前端六阶段工作台、真实 `preview.mp4` 导出、本地 SQLite 项目库。

但距离“最终成品”仍有明显差距：系统看起来像一个分析 demo，而不是一个稳定的一站式创作产品。主要问题集中在四类：

1. 会话、素材、产物的持久化还很轻量，无法支撑长期项目管理。
2. 素材匹配已经可视化，但还不能人工改配、锁定、替换和二次验收。
3. mp4 能导出，但画面包装、素材裁剪、字幕样式、节奏控制仍偏简陋。
4. AI 自动捕获能力有链路，但缺少统一的任务状态、置信度展示和失败兜底体验。

PRD v2 的目标是把项目从“能演示”推进到“能被用户从 0 跑通并可信交付”。

## 2. 最终目标

用户从 0 新建一个会话，上传一个样例爆款视频，再上传自己的素材。系统自动完成：

1. 样例视频结构拆解。
2. 用户素材理解和素材库管理。
3. 样例结构到用户素材的槽位匹配。
4. 缺口识别和 AIGC / 文案 / 包装补全。
5. 多版本方案生成。
6. 可视化预览和人工调整。
7. 导出一个真实可播放的 `mp4`。
8. 保存该会话的全部输入、过程、产物和验收状态。

最终用户不应该看到任何无法解释的 mock 数据。没有分析结果时显示“待分析”；分析失败时显示失败原因和重试入口；有结果时必须能追溯到具体 AI 分析、素材匹配和生成产物。

## 3. 当前已完成能力

### 3.1 后端能力

- 支持样例视频上传并生成 `StructureDNA`。
- 支持用户素材上传并生成 `MaterialLibrary`。
- 支持 `StructureDNA + MaterialLibrary` 生成 `EditPlan`。
- 支持 `balanced / high_click / high_conversion` 三版本方案。
- 支持 AIGC 缺口补全接口；无图片生成配置时降级为文案补全素材。
- 支持 `ffmpeg` 合成真实 `preview.mp4`。
- 新增 SQLite 项目库，保存真实 pipeline 和 preview 地址。
- 新增项目接口：
  - `GET /api/projects`
  - `GET /api/projects/{project_id}`

### 3.2 前端能力

- 左侧会话管理。
- 右侧六阶段流程：
  - 总览
  - 样例分析
  - 素材匹配
  - 方案输出
  - 版本对比
  - 验收清单
- 未分析时分数显示“待分析”，不再默认展示示例分数。
- mock 会话收敛为单个示例会话。
- 素材匹配页升级为三栏工作台：
  - 我的素材库
  - 素材如何放进新视频
  - 当前槽位预览
- 方案输出页支持导出真实 `mp4` 并回填当前会话。
- 前端启动时尝试从项目库恢复真实项目会话。

## 4. 未完成内容评估

### P0：必须完成，否则不能算最终成品

#### 4.1 新建会话完整跑通

当前状态：部分完成。  
问题：

- 新建会话能创建空状态，但还没有统一的“上传样例 + 上传素材 + 开始生成”向导。
- 当前上传入口分散在总览、素材页、方案页，用户不容易知道下一步要做什么。
- 会话阶段没有明确任务状态：排队、分析中、生成中、失败、完成。

目标：

- 新建会话后进入一个明确的上传向导。
- 样例视频、用户素材、目标信息三项输入状态清晰可见。
- 点击“开始生成”后进入统一 pipeline 任务。

验收：

- 用户不看说明，也能完成从新建到导出 mp4。
- 每一步都有 loading、错误、重试。
- 无输入时不展示任何示例结果。

#### 4.2 真实素材管理与人工改配

当前状态：部分完成。  
问题：

- 已能展示素材库和落位关系，但用户不能手动把某个素材拖/选到某个槽位。
- 无法锁定某个匹配结果。
- 无法标记素材不可用、替换素材、重新分析单个素材。

目标：

- 素材库支持素材详情、删除、禁用、重新分析。
- 槽位支持手动选择候选素材。
- 支持“锁定该槽位”，后续重新生成不覆盖人工选择。

验收：

- 用户可把素材 A 指定到 hook 槽位。
- 重新生成方案后，锁定槽位保持不变。
- 每个槽位能解释为什么选择该素材。

#### 4.3 可交付 mp4 质量

当前状态：技术可用，产品不足。  
问题：

- 当前 `preview.mp4` 是简版 ffmpeg 拼接，字幕和包装效果有限。
- 缺少真正的视频编辑器级别的裁剪、缩放、字幕、标题条、转场和节奏控制。
- 横屏素材转竖屏的主体裁剪策略仍粗糙。

目标：

- MVP 阶段继续使用 ffmpeg / Remotion 生成可播放 mp4。
- 增加基础包装模板：
  - 字幕样式
  - 标题条
  - 关键词强调
  - 缺口卡片
  - CTA 收口页
- 后续可切到 Remotion composition 承载更复杂视觉包装。

验收：

- 导出 mp4 必须能播放。
- 每个结构槽位都有可见内容，不出现黑屏空段。
- 缺素材段显示明确的 AIGC / 文案卡补全画面。

#### 4.4 项目数据持久化

当前状态：初版完成。  
问题：

- SQLite 目前只保存项目 JSON 和 preview URL。
- 没有素材表、文件表、任务表、版本表。
- 没有会话删除、重命名、复制、导出项目包。

目标：

- 建立正式数据模型：
  - projects
  - assets
  - pipeline_runs
  - edit_plans
  - renders
  - manual_overrides
- 前端会话列表完全来自项目库和当前本地草稿。

验收：

- 刷新页面后真实项目不丢。
- 每个项目能恢复上次的素材、方案、预览视频。
- 删除项目后本地数据库状态同步。

### P1：影响产品可信度和答辩表现

#### 4.5 AI 分析置信度和过程解释

当前状态：部分完成。  
问题：

- `StructureDNA` 有 `confidence` / `analysis_reason`，但前端没有形成统一解释层。
- `MaterialLibrary` 的 `analysis_source` 有展示，但缺少“为什么识别成这个语义角色”。
- 用户无法区分 ASR、VLM、LLM、规则兜底分别产生了什么。

目标：

- 每个阶段展示：
  - AI 来源
  - 置信度
  - 失败原因
  - 兜底策略
- 总览提供一条 pipeline 日志。

验收：

- 任意一个槽位都能解释：样例怎么拆、素材怎么选、脚本怎么生成。
- 失败时能定位是 ASR、素材识别、计划生成还是渲染失败。

#### 4.6 多版本生成闭环

当前状态：部分完成。  
问题：

- 已有三版本生成和对比，但版本产物还停留在 `EditPlan` 对比。
- 没有分别导出三个版本的 mp4。
- 没有版本间差异摘要和推荐理由。

目标：

- 三个版本都能生成独立 `EditPlan`。
- 可选择任一版本导出 mp4。
- 系统推荐一个版本，并说明理由。

验收：

- 用户可以切换三版本，看到脚本、节奏、素材落位和 preview 差异。
- 选择版本后导出对应 mp4。

#### 4.7 验收清单产品化

当前状态：展示为主。  
问题：

- 验收清单还不是基于真实状态自动计算。
- 缺少“未通过项 -> 去修复”的跳转。

目标：

- 根据 pipeline 产物自动计算验收项。
- 每个未通过项能跳到对应页面修复。

验收：

- 没有 preview mp4 时，验收项显示未通过。
- 点击“缺素材未处理”跳到素材匹配页对应槽位。

### P2：最终上线和规模化需要

#### 4.8 异步任务系统

当前状态：未完成。  
问题：

- 上传、ASR、VLM、渲染都是同步请求，长视频容易超时。

目标：

- 引入 job 模型：
  - `job_id`
  - `status`
  - `progress`
  - `logs`
  - `result`

验收：

- 前端可轮询任务状态。
- 后端重启后任务状态可恢复。

#### 4.9 对象存储与部署

当前状态：未完成。  
问题：

- 文件都在本地 `outputs/`。
- 没有对象存储、CDN、生产域名和鉴权。

目标：

- 本地模式继续保留。
- 部署模式支持 OSS/S3。
- provider key 只在服务端环境变量中配置。

验收：

- 生产环境上传文件不依赖本地磁盘持久性。
- preview URL 可公网访问。

## 5. PRD v2 功能范围

### 5.1 P0 版本页面结构

左侧：会话管理

- 新建会话
- 会话列表
- 会话阶段
- 会话产物状态

右侧：六阶段主流程

1. 总览
2. 样例分析
3. 素材匹配
4. 方案输出
5. 版本对比
6. 验收清单

总览只显示当前真实状态，不显示 mock 分数。

### 5.2 样例分析

输入：

- 样例视频

输出：

- 基础信息
- ASR 文本
- 结构槽位
- 结构公式
- 情绪 / 节奏曲线
- 分析置信度

关键交互：

- 重新分析
- 查看原视频
- 查看每段识别原因

### 5.3 素材匹配

输入：

- 用户视频 / 图片 / 文案 / 音频素材

输出：

- 素材库
- 素材标签
- 素材质量分
- 槽位匹配
- 缺口报告

关键交互：

- 上传素材
- 删除素材
- 重新分析素材
- 手动指定素材到槽位
- 锁定槽位
- AIGC 补全

### 5.4 方案输出

输入：

- Structure DNA
- Material Library
- 版本配置
- 人工微调

输出：

- Edit Plan
- 时间线
- 字幕 / 标题条 / CTA
- preview mp4

关键交互：

- 一句话改片
- 修改 Hook
- 修改 CTA
- 修改包装风格
- 修改节奏强度
- 导出 mp4

### 5.5 版本对比

输出：

- 平衡版
- 高点击版
- 高转化版

关键交互：

- 查看差异
- 选择版本
- 导出当前版本

### 5.6 验收清单

验收项：

- 样例是否解析完成
- 用户素材是否存在
- 每个槽位是否有落位或补全策略
- 是否生成 Edit Plan
- 是否导出 preview mp4
- 是否存在缺口未处理
- 是否有可解释报告

## 9. 风险与约束

- ASR / VLM / LLM provider 稳定性会直接影响自动分析质量。
- 长视频和大素材同步处理容易超时，必须尽快任务化。
- mp4 质量短期依赖 ffmpeg 简版合成，复杂包装建议逐步迁移到 Remotion composition。
- 当前数据库适合本地 MVP，不适合作为多人生产系统。
- AIGC 图像补全需要明确 provider 配置，否则只能降级为文案卡。

## 10. 下一步建议

优先顺序：

1. 做新建会话向导，把上传样例、上传素材、开始生成收敛到一个入口。
2. 做手动素材改配和锁定槽位。
3. 做验收清单真实状态计算和跳转修复。
4. 做 preview mp4 的包装模板升级。
5. 做异步 job 和项目删除/重命名。

一句话判断：当前项目已经从 mock demo 进入真实 MVP 初期，但最终成品的关键不是再加页面，而是把“会话状态、素材管理、槽位可控、mp4 交付、项目持久化”全部收敛成一条可信闭环。
